## 发现（按优先级）

### P0 — 卡片导出是高价值功能，却被埋没
- `CardPanel.tsx`：把 AI 回复渲染成**可导出的样式卡片图**（米白/纯白/天青/暮光/墨黑背景、窄/中/宽、内边距、圆角、导出 PNG）。这正是小红书/公众号创作者最想要的「文字转配图」。
- 问题：①藏在 48px 右 dock 的一个图标后；②只在对话视图；③只预览**最后一条** assistant 消息。装配初稿、改写成稿、任意消息都用不到它。
- **建议**：把「导出为卡片图」提升为一等动作 —— 在消息气泡、装配初稿弹窗、改写成稿卡片上都给入口；卡片面板支持选任意文本，而非只取最后一条。

### P1 — 右侧栏只在对话视图出现，心智不一致
- 切到素材库/选题库时右边的 dock/panel 消失，切回对话又出现 → 右边缘的存在感闪烁。
- **建议**：二选一。(a) 让右侧「辅助面板」在所有视图一致存在（统一的参考/卡片/反链侧栏）；或 (b) 干脆去掉 chat 专属右 dock，把其功能并入下面说的统一机制。

### P1 — 分屏 vs 右侧面板：两套并排机制重叠
- 既有「分屏」（44%，用原生 `<select>` 选内容）又有「右侧 dock/panel」，都解决「边看边写」。两套模型并存让人困惑。
- **建议**：统一为**一个右侧辅助栏**（可放：卡片导出 / 某个参考视图 / 反链）；分屏只保留给「两个对话并排」这一明确场景。原生 select 换成与 app 一致的下拉/命令。

### P2 — 「文件」面板是开发向遗留
- `FilesList` 展示项目绑定目录的文件，是配合「编程」视图的 dev 概念；对纯创作者价值低，却和「卡片预览」并列占据右 dock。
- **建议**：随「编程/浏览器」一起降级到「工具」语境，右 dock 不再一半是 dev 功能。

### P2 — 顶部 chrome 三层叠加，垂直空间偏奢侈
- TitleBar(40) + WorkspaceTabs(40) + TabBar(36) ≈ 116px 才到内容。
- **建议**：工作区切换可并入标题栏右侧或侧栏顶部；对话 tab 与拖拽区合并，省一层。目标把顶部压到 ~72px。

### P3 — 「打开的东西」有三处管理
- 工作区 tab（顶）、对话 tab（TabBar）、侧栏对话列表 —— 三处并存、概念重叠。
- **建议**：长期可收敛为「侧栏管空间/对话，顶部只留当前对话 tab」，减少一层。

### P3 — 宽屏下主列空旷
- 多数视图 `max-w-2xl` 居中，宽窗时中间留白大。阅读类（对话/笔记）合理，但数据密集类（发布数据/图谱/素材库）可放宽到 `max-w-4xl`+ 更好利用空间。

---

## 推荐落地顺序（若要做）

1. **P0 卡片导出提级**（对创作者最直接的价值）——独立小切片，先做。
2. **P1 统一右侧辅助栏 + 收敛分屏语义**——结构性，改动中等，建议进 plan 模式细化。
3. **P2 顶部 chrome 瘦身 + 文件面板降级**——中等。
4. **P3 收敛「打开的东西」/ 宽屏利用**——较大，后做或不做。

> 侧栏分组（本次已完成）+ P0 卡片提级，能以很小代价显著拉高「像给内容创作者做的」观感；P1 是真正的结构性重构，值得单独规划。
